## 公开接口（以 rank.h 为准）

```c
#define CUSTOM_RANK_FORMULA_VERSION 1
#define CUSTOM_RANK_TOP 5

typedef struct {
    int formulaVersion;
    int rows, cols;
    int previewMillis;
} CustomRankConfig;

int saveCustomScore(const char name[], const CustomRankConfig *config,
                    int finalScore, long long elapsedMillis);
int resetCustomRankPage(const CustomRankConfig *config);
int updateCustomRankPage(void);
void drawCustomRankPage(Font font);
```

不让 rank.h 依赖 game.h。排行榜接收已经冻结的最终积分，不依赖游戏全局状态，不重新计算倍率。用户名高亮复用 `setCurrentPlayer(user.name)`。

- `saveCustomScore`：1 更新并保存；0 未刷新个人最好或未进前五；-1 参数、格式、资源容量或文件错误。0 不表示已保存此次成绩。失败不得更新成功状态或破坏旧成绩。
- `resetCustomRankPage`：复制配置键，读取并准备页面；1 成功（空榜也是成功），-1 失败并保留可绘制的错误提示。返回 -1 时主流程仍可显示页面，用户能够返回或重试。
- `updateCustomRankPage`：0 留在页内，1 返回玩家菜单。页面支持浏览已有记录的其他配置，以及重新读取；空榜时也能返回。配置切换只影响榜单视图，不修改正在编辑的游戏参数。
- `drawCustomRankPage`：只绘图，不能在逐帧绘制时读盘、写盘或提交成绩。

## 分榜与排序

配置键为 `(formulaVersion, rows, cols, previewMillis)`，四项必须完全相同。4×5 与 5×4 分开；不同预览时间、不同公式版本分开。不要制作所有配置混排的总榜。

当前只支持公式版本 1；rows、cols 各 2～6，总牌数须偶数；previewMillis 为 1000～30000。两张配对、错配锁定 1 秒、主动亮牌 4 秒是版本 1 固定规则，不必重复保存到配置键。

每个配置保留前五名，同名只留个人最好。积分降序；同分按耗时毫秒升序；仍相同时保留先入榜者的相对顺序。同一玩家同分更慢或完全相同，不更新；同分更快则更新。零分、零毫秒属于接口合法边界值。主动亮牌不取消自定义成绩资格。

用户名沿用账号约束：1～31 字节、以 NUL 结束且不含空白。禁止截断长用户名后入榜，禁止空指针、负分、负时间。时间用 long long；比较使用关系运算，避免相减溢出。

## 存档协议与失败行为

只使用独立的 `custom_ranks.txt`（运行工作目录），普通 `ranks.txt` 的接口、内容与格式保持不变。`.gitignore` 已排除新存档及临时文件；不要提交真实玩家数据。

UTF-8 文本。首行固定：

```text
MC_CUSTOM_RANKS 1
```

后续每条记录恰好七列：

```text
公式版本 行数 列数 预览毫秒 最终积分 耗时毫秒 用户名
1 4 4 5000 594 20000 demo_player
```

首行的 1 是文件格式版本；每条记录的第一个字段是公式版本，二者不可混用。时间输出用 `%lld`。不同配置的记录均须保留；同一配置的文件记录顺序就是完全同分同耗时时的先后顺序。可统一用稳定排序整理，每配置最多五条。

- 文件不存在（ENOENT）按空榜处理；权限错误、读失败、格式不支持不能当成空榜。
- 严格校验字段、整数范围、行长度与额外非空字段；空行可忽略。坏行、重复的同配置同名记录、同配置超过五条、未知公式版本均报格式错误，停止写入，不静默丢掉原记录后重写。合法但未排序的五条以内记录可稳定排序。
- 若使用固定容量，达到容量时明确报错，不能截断其他配置；也可按实际文件动态分配，检查分配失败并释放内存。
- 先在临时内存中完成新榜，再写同目录 `custom_ranks.txt.tmp`。逐项检查输出、flush、close 和最终替换结果。临时写失败或替换失败均返回 -1，原目标文件保持完整，内存回滚。使用 Windows 可替换已存在目标的文件替换方式，不要先删除旧文件再 rename。临时文件不能被当成正式榜单加载。
- 单个游戏进程使用；多进程并发写入不属于本版范围。
- 读取和持久化在 save/reset/update 中进行；draw 只显示快照和错误。每次打开榜单或保存前读取当前存档，避免永久缓存曾经的空榜/错误；重试必须能恢复。

## 页面要求

沿用 800×600 逻辑坐标、公共字体、按钮与相机。标题“自定义积分榜”，显示公式版本、行列、预览秒数，再显示名次、用户名、最终积分、用时（毫秒转换为秒，建议三位小数）。每页五名，高亮当前玩家。

提供上一个/下一个已有配置、重新读取和返回菜单按钮。打开时先显示请求配置，即使它暂无成绩；切换列表包含请求配置与已有记录配置，去重并按四元组升序排列。无其他配置时切换无效。读取失败时禁用配置切换，但重试与返回仍可用。明确显示“暂无成绩”“积分榜读取失败”等状态，不能用空榜掩盖错误。

## 主流程接入约定（由主流程负责人实施）

目前 main.c 尚未调用这些接口，因为 rank.c 尚未实现。不要先增加空壳返回成功让界面误报已保存。

1. main.c 增加 `PAGE_CUSTOM_RANK`。菜单“排行榜”仍进入普通榜；自定义设置页增加“查看此配置榜单”，按当前合法配置打开；自定义结算页增加“查看此配置榜单”。这两个入口都调用 setCurrentPlayer、resetCustomRankPage，然后进入新页面。
2. 开局时复制一份实际启动配置；结算保存与结算榜入口使用这份配置，不能误用后来编辑过的配置。配置键中的 previewMillis = `floor(previewSeconds * 1000 + 0.5)`。当前 UI 是整秒档；排行榜边界以毫秒为准。将来支持小于毫秒的配置时必须先约定规范化规则，不能直接混用浮点字符串。
3. 仅在 `updateGame(&seconds)` 返回 1 且 `getCustomGameResult(&result)` 成功的那个更新分支，调用一次 saveCustomScore。传入 result.finalScore 与 `floor(result.elapsedSeconds * 1000 + 0.5)` 转成的 long long；转换前校验有限、非负且结果小于 2^63，避免越界转换。分数仍用原 double 时间计算，不能用保存时的毫秒反算积分。
4. 保存失败显示“积分保存失败”；返回 0 显示“未刷新成绩或未进入前五”；返回 1 显示“积分已保存”。结算页重绘、打开榜单、切换配置均不重复保存。
5. 自定义局使用亮牌仍可保存，不能走普通模式 `!getGameCheats()` 的门槛。退出、关窗、未通关、无效配置均不调用 saveCustomScore。
6. 新页面每帧 updateCustomRankPage，返回 1 时回玩家菜单；绘制阶段调用 drawCustomRankPage。reset 失败仍显示该页面的错误状态。
